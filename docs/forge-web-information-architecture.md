# Forge Web 信息架构与命名规范

## 目标

Forge Web 面向的是需要查找、理解、预览和安装卡片能力的使用者。页面首先表达用户任务，不直接暴露服务端运行模式、构建产物或渲染实现。

## 一级导航

| 入口 | 用户任务 | 页面应回答的问题 |
| --- | --- | --- |
| 卡片 | 查找和查看已有卡片 | 有哪些卡片？不同示例实际长什么样？需要什么数据？ |
| 组件规范 | 查阅可复用的视觉与结构规范 | 可以使用哪些组件、组合和样式？ |
| 预览调试 | 输入 JSON 并检查渲染结果 | 这份卡片数据最终会显示成什么样？ |
| 安装 | 获取并初始化工具 | 如何开始使用？还有哪些可选安装方式？ |

## 展示原则

1. 页面标题、操作名称、状态反馈和空状态统一使用简洁中文。
2. `Workspace`、`Published`、`Snapshot`、`Artifact`、`Compiler`、`Render Profile`、`Wire Profile`、SDK 版本、Commit 和 SHA 不作为一级信息。
3. 对排障仍有价值的版本号、引用、摘要和来源统一收进默认折叠的“技术信息”。
4. 工作区服务与发布服务可以使用不同数据接口，但必须呈现为同一个产品，不在导航和页面标题中区分运行模式。
5. 默认视图优先展示结果；JSON、检查报告和版本记录按需展开。

## 页面结构

### 卡片

- 左侧：搜索和卡片列表。
- 右侧顶部：卡片名称、引用、必要状态和主要操作。
- 内容页签：`预览`、`数据结构`、`检查结果`。
- 版本选择仅在存在多个版本时展示。
- 视图与示例选择使用 `状态`、`示例` 命名。
- 交付下载使用“下载交付包”。

### 组件规范

- 页面标题不展示 Profile 引用。
- 分类统一为：`全部`、`基础规范`、`基础组件`、`样式工具`、`组合模式`。
- 每个条目默认展示说明和效果；JSON 代码按需展开。

### 预览调试

- 默认仅提供“卡片 JSON”编辑与预览。
- 服务端支持模板数据时才展示“模板数据”模式。
- 不展示编译器连接、SDK 版本和 Profile 标识。
- 操作统一为“格式化”和“预览”，状态统一为“预览已更新”或明确错误。

### 安装

- 首屏只保留推荐的两步安装流程。
- Skill 包作为可选方案展示。
- 版本兼容信息保持简洁；SHA 等校验信息收进“技术信息”。
